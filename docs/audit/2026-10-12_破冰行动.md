## 修复清单

### Fix 1 · 频率闸门
- **问题**：企微「选不出票」复盘每日推送约 14 次。
- **根因**：`review_nopick` 步骤挂在 `intraday` job 内（cron `0,30 1-7 * * 1-5` UTC = 北京 09:00–15:30 每 30 分钟 tick），且无频率闸门；落地脚本 `scripts/review_nopick.mjs` → `push_review_wechat.mjs` 的 `findLatestReview()` 只取最新文件直推、**无任何去重态**。
- **修复**：给「复盘归因」与「推送复盘到企业微信」两步加 cron 闸门，仅北京 14:00 那档 + 手动触发放行。
  - `.github/workflows/daily.yml`：`if: github.event.schedule == '0 6 * * 1-5' || github.event_name == 'workflow_dispatch'`（UTC `0 6` = 北京 14:00），两步同闸门。
- **效果**：每日刷屏 14 次 → 仅 14:00 一档 + 手动。

### Fix 2 · 双端同源
- **问题**：公开页面外围区绕过 `validateExternal`，陈旧富时A50 仍当「今日数字」显示，与推送/报告端结论分叉（即 10-12 报告那条残留疑点根因：不是没修，是页面渲染分支漏接）。
- **根因**：刚落地的外围兜底规则只在报告/推送链路生效；`app.js::renderGlobal` 直读 `g.quotes`（`q.chgPctText`/`q.lastText`/`globWhen(q)`），未调 `validateExternal`。
- **修复**：页面渲染端复用与推送端同源的判据，并对三处同源模块补齐守卫，杜绝再次分叉：
  - `app.js:3084-3089`：`renderGlobal` 改为 `window.ValidateExternal.validateExternal`，缺模块时安全降级直读、不冒充。
  - `validateExternal` 实现位于 `src/validate_snapshot.js`（陈旧≥2天置空 / 当日失败保留+标记）。
  - 三处同源守卫补齐：`sw.js`（+1）、`src/offline.js`（+1）、`.github/workflows/deploy-pages.yml`（+1），与 `index.html`（+1）一同确保离线/部署面加载同一份校验模块。
- **效果**：页面 / 报告 / 推送三端外围数据判据统一，不再分叉。

### Fix 3 · 时区纪律
- **问题**：北京 00:00–08:00 期间日期错位「昨日」，即时轨整体偏一天（同类于 `ai_report.js` 此前修过的「盘中标昨日」复现）。
- **根因**：`src/` 内两处裸用 UTC 取日期，违反 `src/time.js` 纪律（「除本模块外不得出现时区字面量」）：
  - `src/report_card_live.js:68` 原 `new Date().toISOString().slice(0,10)`
  - `src/intraday_sampler.js:69` 原 `todayStr()` 同款
- **修复**：统一走 `bjDate()`（`src/time.js`）：
  - `src/intraday_sampler.js:20` `import { bjDate } from './time.js'`；`:70` `todayStr()` 改为 `return bjDate();`
  - `src/report_card_live.js:29` `import { bjDate } from './time.js'`；`:69` `const today = io.today || bjDate;`
- **效果**：00:00–08:00 日期错位彻底消除，即时轨 `dayKey` / 实时权益序列 / `window.__intradayLive.tradeDate` 一致。

### Fix 4 · 去重统一
- **问题**：页面即时轨走 Worker→企微、CI 即时轨走 `ai_report_push`→同一企微机器人，二者去重算法/存储隔离，内容重叠时可能双推同一 intraday。
- **根因**：Worker `proxyFingerprint`（djb2，自实现）与 CI `fingerprintOf`（sha256，自实现）**算法不同、KV/文件存储隔离**（指纹稳定域其实一致，但实现副本必然日后漂移）。
- **修复**：全系统指纹统一到唯一实现 `src/push_text.js::fingerprintOf`（djb2，三端同构）：
  - `src/ai_report_push.js:28` `import { ..., fingerprintOf } from './push_text.js'`；`:43` `const fp = fingerprintOf(report);`
  - `worker/push_proxy.js:26` re-export `fingerprintOf`；`:27` 本地渲染/清洗显式 import；`:130-132` `export const proxyFingerprint = fingerprintOf;`
- **效果**：Worker 与 CI 指纹算法、稳定域完全对齐，单一实现，杜绝日后副本漂移导致双推。

## 架构原则（禁止回退）

1. **双端同源**：页面 / 推送 / 报告对同一数据的判据必须同源，禁止各自实现。新增前端取数必须复用既有校验模块（现 `src/validate_snapshot.js`），不得直读原始 JSON 字段后自行解释。
2. **频率闸门**：任何推送类步骤（企微 / 群机器人 / 邮件）必须有去重态 **或** cron 闸门。挂在高频 job 内的推送步骤一律加 `if: github.event.schedule == <指定档> || github.event_name == 'workflow_dispatch'`。
3. **时区纪律**：`src/` 下禁止裸用 `new Date().toISOString()` / `Date.now()` 做日期截断，统一走 `src/time.js`（`bjDate` / `bjNow`）。时区字面量只许出现在 `time.js` 内部。
4. **去重统一**：指纹算法全系统唯一实现（`src/push_text.js::fingerprintOf`），禁止在 Worker / CI / 前端另写副本。改指纹请改这一处，三端自动同步。
