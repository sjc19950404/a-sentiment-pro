# 数据缺口台账

> 归档序列（`data/archive.json`）里**缺失的交易日**记录。
>
> 为什么要有这份台账：**跨档审计是锚点式比对**（各档 vs 档案锚），天生看不见"序列中间
> 少一天"。一旦锚点跳到更新的交易日，缺口会被静默跨过去——`freshness` 落后数归零转绿、
> 审计转绿，**没有任何门禁会再提起它**。所以缺口必须在这里留痕，否则将来查序列时
> 发现少一天，只能重新考古一遍。

### 2026-10-09 裁决理由

1. **不紧急**：与 ztpool 不同，这一天的派生档**随时可补**——历史日线可由 BaoStock 按日期
   区间取得（`market_data.py` 的 `fetch_history_daily`，本机可达）。延后补不产生不可逆损失。
2. **补了也不进回测**：回填天必须打 `_backfill` 标记（否则就是"旧值顶替当日值"，
   正是 `534df3d` 双闸要根治的事故类型），而回测脚本**显式排除 `_backfill` 天**。
   故补录的净收益只剩"序列连续"，不提升指标/回测样本；成本是新编排代码 + 写生产档。
3. **收益/成本不支持**：仅为一天派生档写"按日期新增归档天"的编排，风险大于收益。

### 实测支撑（2026-10-10，三变体实验）

在**临时副本**上跑了三个变体（统一用 `--archive` 指向 `%TEMP%`，生产档未动），
由 `node scripts/freshness.mjs` 与 `node scripts/backtest.mjs` 实测：

| 变体 | freshness 判定 | 回测样本 |
|---|---|---|
| 原档（不补） | behind / 落后 1 | 242 天 |
| A：只加序列、**不打标记** | behind / 落后 1（**没变**） | **243 天（被纳入 → 污染）** |
| B：只加序列、打 `_backfill` | behind / 落后 1（**没变**） | 242 天（排除 → 无增益） |
| C：序列 + **改 `meta.tradeDate`** + 标记 | **fresh / 落后 0** | 242 天（排除） |

由此坐实两条（补录时不可跳过）：

1. **只补序列没用**：`freshness` 读的是 `meta.tradeDate`，不是 `all_days` 尾部。
   不改 meta，补了仍判定 behind（三个变体一致）。→ 补录实为**两处写操作**，
   且新增"meta 与序列不一致"这一失败模式。
2. **不打 `_backfill` 会污染回测**：242 → **243 天**，该天被当成真样本纳入。
   这正是源码注释"208 天假情绪分会污染每个指标"的真实机制。

### 若将来要补（路径已备，随时可走 · 已按实测修正）

1. 用 BaoStock 取 **2026-10-08** 全市场日 K → 走 `src/zt_rebuild.js` 重建 → 与档案里
   **真实的 10-08** 逐字段交叉验证（口径校验；`backfill_factors.mjs --validate` 同款机制）。
2. 验证通过 → 取 10-09 日 K → 写入 `all_days` 该天，**必须打 `_backfill` 标记**
   （不打会被回测纳入，实测 243 天——见上表变体 A）。
3. **同步把 `meta.tradeDate` 改为 `2026-10-09`**——不改则 freshness 仍判定 behind
   （实测变体 B 已证，这是最容易漏的一步）。
4. `recalcAll` + 切片重建。
5. 跑全套：`node --test` + `check_contract.mjs` + `audit_data_caliber.mjs` 确认无回归。
6. **任一步校验不通过就停下不补**（宁缺毋假）。

### 附带结论：本地 `bt_kline` 停在 09-30，不用管

曾担心"K 线缺 10-08/10-09 → 周一 10-12 的连板梯队会算错"。实测排除该风险：

- **10-09 涨停池自带 `lbc`（连板数）**：69 条记录字段含 `lbc` / `lbt`，连板高度已在库，
  不可补的那层没丢。
- **日产连板取池、不取 K 线**：归档 `max_lb` 与东财池最大 `lbc` 逐日吻合
  （09-30：7 / 7；10-08：8 / 8），`src/ai_report.js` 亦明写 `pools.zt_lb` 为唯一权威源。
- **K 线回溯（`src/zt_rebuild.js`）只在回填历史天时才走**——默认不回填，就不经过这条路。

→ 10-12 的连板梯队不受 10-09 缺口影响；K 线缺口无需专门处理。

### 改判条件（满足任一即值得补）

- 在册缺口扩大到 **≥2 个交易日**（单点洞变成段，统计偏移不再是误差级别）
- 某个具体功能被确认因缺口出错（健康面板近 N 日统计、连板梯队链等）
- 需要这一天进入回测样本（那要先过上面的口径 validate，升级为真分，工程量更大）
