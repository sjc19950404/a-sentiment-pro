| 项 | 结果 |

**不进降级链**（理由见 §3）。

## 2. 降级链结构

```
① 东财 push2ex getTopicZTPool       主源（全字段，一次拉全市场）
        ↓ 空 / 失败
② AkShare zt_pool（market_data.fetch_zt_pools）   第一备源（同源同端点，四项实测等价）
        ↓ 失败
③ 腾讯 gtimg 零鉴权快照             弱兜底（字段最弱，需先验证可用性）
        ↓ 都失败
④ 标记 gap → 企微告警 + 缺口台账      不补数（宁缺毋假）
```

**每层都必须带 `source` + `degraded` 标记**（见 §5）——否则下游会在不知情的情况下用弱口径数据，
那正是 10-08 事故的类型（"看到连板数却不知道口径是哪天的"）。

## 3. QuantDash 的定位：校验器，不是备源

| | 结论 |
|---|---|
| 速度 | 不是问题——实测 500/批 ×8 = 3309 行 / 13.9s |
| **配额** | 免费版 **10 次/分钟**，全市场 8 请求刚好卡满，**无重试余量** |
| **字段** | **无 `fbt` / `fund` / `lbc`** ——它是**快照**，不是"池" |
| 决策 | 把"没连板数的快照"塞进"池"的降级链，下游会拿到两种口径的池，难处理 → **不进链** |

它的正确用途：验证涨停价公式能否用 `prev_close` 复现（已验：三板块命中），以及将来做小样本交叉核验。

## 5. `degraded` 标记规则

入库结构（`data/ztpool_history.json` 每条）：

```json
{ "date": "20261012", "pool": [ ... ],
  "source": "em | akshare | gtimg",
  "degraded": false }
```

| 规则 | 说明 |
|---|---|
| `source` 必填 | 缺省视为 `em`（历史档），新写入必须显式带 |
| `degraded = source !== 'em'` | 非主源即降级，下游按弱口径处理 |
| 下游处理 | `fbt` 缺席 → **不剔不猜**，basis 报因（已有机制）；`fund` 缺席 → 封单质量报因；`lbc` 无法取得 → `null` |
| 入库核验（`cron.md §6`） | 现有四条核验外补一条：**`source`/`degraded` 字段存在且取值合法** |
| 禁止 | 用降级数据冒充主源数据（`degraded` 不得手写为 `false`） |

## 6. Gap 台账格式（写入 `docs/data-gaps.md`）

| 交易日 | 缺口范围 | 成因 | 上游原料状态 | 裁决 | 记录日 |
|---|---|---|---|---|---|

涨停池缺失时必填：`成因` 写明"主源与备源均失败 / 备源字段不全"，`上游原料状态` 写明
"该日涨停池不可回补（东财只给最近交易日）"，`裁决` 默认"接受缺口，不回补"。

## 7. 告警阈值

| 触发条件 | 级别 | 通道 |
|---|---|---|
| 主源失败 → 备源成功 | **warn** | 企微（提示当日走备源，`degraded: true`） |
| 主源 + 备源 + gtimg 全失败 | **error** | 企微 + 台账记 gap（不补数） |
| 对照：名单一致率 < 99% | warn | 企微（备源资格存疑） |
| 对照：`lbc` 一致率 < 99% | warn | 企微 |
| 对照：`fbt` 或 `fund` 齐全率 < 100% | **error** | 企微（备源不合格，一字板/封单判据会失效） |
| 对照脚本自身失败 | 不告警 | 仅打印警告——**不污染主任务退出码** |
