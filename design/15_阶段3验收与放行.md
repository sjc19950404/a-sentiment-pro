## 4. 探针迭代：5 次实跑中甄别的口径错误与时序噪声

前几轮教训是"假绿/假红都要追根因"。本轮主探针跑了 5 次才拿干净结果，逐条记录（**均为探针问题，非代码缺陷**）：

| 轮次 | 现象 | 根因 | 处置 |
|---|---|---|---|
| 1 | 7 项 false | `g1` 把 LW 自带 svg 点赞图标误判为 SVG 兜底；`g4/g9` 把 `#btStrategyPanel` 限定在 `<main>` 内（它本就在 main 外，index.html L972）；`g9_main_at_top` 误要求 main rectTop=0（前面有 12 个异步面板，459 正常） | 修探针判据：canvas+ready 为准；旧表格"全局存在+不在 sRoot"；删 main_at_top 改 main 可见 |
| 1 | 涨跌停 8s 超时 | 探针用 `typeof S` 判定失误 + 测试顺序累积 | 改 `window.S` 判定 + 延长等待；专项复测 **2854ms 到位**（涨停 37/炸板 80） |
| 2–3 | 回测 8 项 false | 就绪标志用阶段 1 的 `#sRoot`（骨架先出现），切 tab 抢在 page 注册前 | 改就绪标志为阶段 3 专属 `registerPageBacktest/registerPageZt` |
| 3–5 | 回测仍 error | 沙箱代理 `https_proxy` 对 R2 CDN 与 github.io 同源处理不同；且自动化多 case 连续导航下首切回测偶发"fetch 成功但 createChart 未就绪" | 改无代理；加"首切未就绪则重切一次" |

**决定性对照**（`阶段3回测首切专项.json`）：
- 阶段3标志/LW 未就绪时切回测 → fetch 200 但 `data-state=error`（createChart 无 LW）。
- 等 LW 就绪后切 → `canvasWait=811ms`、canvas 840×350、265 行、KPI 全值。
- 主探针加入"重切重试"后 → 首切 4864ms 就绪，29/29。

**对真实用户的影响判定**：无。真实用户点 tab 时页面早已加载完（vendor LW 是 index.html L1452 的同步阻塞 `<script>`，bundle.js 是 defer），`window.LightweightCharts` 必然就绪。该时序噪声只在自动化脚本"半加载态模拟点击"时出现，故归为探针问题，不要求 CodeBuddy 改代码。
