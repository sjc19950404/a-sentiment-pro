## 三句话结论

1. **问题不是审美，是信息架构没分层**：14 类功能平级平铺，58% 屏幕给了模拟盘 + 回测（操作/审计），只有 17% 回答「今天盘面有什么风险」；为压 CLS 而锁死高度，又制造了 18 处盒内滚动和半截字裁切。
2. **不需要从零设计**：系统里的「研究工作台」已经是正确答案（结论指标条 → 走势大图 → 因子仪表、12 列栅格、整页滚动、8 tab 中 6 个完整可用），方案是把它升为主视图，不造第三套 UI。
3. **桌面 + 移动同一套代码**：四档断点、列优先级、抽屉三档（移动端全屏 sheet）、骨架原位替换，实测横向溢出 0、盒内滚动 0、桌面 1883px / 移动 3170px。

## 方案要点（可直接写进任务单）

| 项 | 决策 |
|---|---|
| 主方案 | **A**：工作台升主视图；研报视图降级为打印 / 导出 / 长文阅读页。B 方案作为 10 人日低风险过渡路径保留 |
| 信息架构 | 结论层（常驻、≥40%）→ 证据层（整页滚动、约 42%）→ 操作层（tab + 抽屉、≤18%） |
| 导航 | 9 tab；移动端「底部 5 项 + 更多抽屉」；深链 `?view=terminal` / `#terminal` 幂等可达 |
| 视觉 | 继承 `.t-` 设计纪律（chrome 柔 / 数据锐、辉光只三处、动画只 opacity+transform、禁 backdrop-filter）；统一为 151 个 `--s-*` 令牌，深浅双主题；**红涨绿跌** + 符号冗余 |
| 响应式 | `<640` / `640–1023` / `1024–1439` / `≥1440`；表格 `data-priority` 列分级；抽屉三档 420/640/960，<640 全屏 |
| CLS 治理 | **骨架占位 + 内容原位替换**替代「锁死高度 + 盒内滚动」。实测真实卡与骨架卡同为 134px、两态页高同为 1883px，位移 0 |
| 不可复活 | 逐个加 min-height、关 smooth / overflow-anchor、main 加 contain、main 固定高、放大 btStrategyPanel、去掉高度上限（均已被站点实证证伪） |
| 数据层 | **零改动**：34 个 `data/*.json`、54 个 `function render*`（app.js 38 + bundle.js 17，去重后 54）、LINK 总线协议全部保留，只加展示层适配 |

## 原型怎么玩

双击 `prototype/index.html`（无需服务器、无需网络）。可用深链稳定复现每种状态：

| 参数 | 效果 |
|---|---|
| `?view=backtest` / `?view=paper` / `?view=zt` | 切到指定视图 |
| `&demo=drawer` / `drawer-small` / `drawer-more` | 打开加宽 / 默认 / 更多抽屉 |
| `&demo=skeleton` | 骨架态 |
| `&theme=light` | 浅色主题 |

页面内还可点：顶部时间窗 20/30/60/90（实时重绘走势图）、表格行（开抽屉）、「展开」告警折叠条、浅色 / 刷新 / 骨架态按钮、底部 5 tab。

## 自检与复现

```bash
node design/shots.cjs         # 渲染 12 张视觉稿 + 横向溢出/盒内滚动自检
node design/measure.cjs       # 量测骨架与真实卡高度差（应同为 134px）
node design/sync_tokens.cjs   # 改令牌后同步视觉册第 8 节
node design/build_doc.cjs     # 重新汇编 UI设计方案.html
```

`assets/自检报告.json` 是 12 种视口 / 状态的原始自检数据。全部结果：**横向溢出 0、盒内滚动 0（抽屉 body 白名单 1 处）、桌面页高 1883px、移动页高 3170px**。

## 边界与如实说明

- 本次**未改线上代码、未发布、未触发任何写操作**（保存并写盘 / 重置账户 / 提交委托等）。
- 客观不可见：`intradayCard` 盘中态（非交易日 `display:none`）、真机树莓派性能、隧道写接口、移动端触摸态 tooltip。
- 设计目标与原型实测有一处取舍：分册 01 的极简目标「6 指标 ≤184px / 38.4 @96px」，原型为可读性保留了 tab 导航与一句话风险结论条，实测 6 指标约 372px、38.4 约 260px（仍远早于旧版 459px，且都在首屏内）。主文档第 8 节写明如何切到紧凑版。
- 打印版 PDF 不含分册折叠全文（避免数百页）；分册全文在 `UI设计方案.html` 的「9 · 分册全文」与独立 Markdown 文件中。
- **05 册 5.1 的自检脚本（`S.runSelfTest()` / `collectCls()`）是阶段 0 要新增实现的文件，不是仓库现成工具**。CLS 判定已修为双档（`target 0.10` 放行 / `baseline 0.174` 仅标记退化）、观测窗口 5 秒；`npm run lh` 与 `.lighthouse/baseline.json` 属于 Lighthouse 侧复核，不替代 CDP 自检。
- **深链验收不能用 `curl 200`**：静态 Pages 任何 query 都返回同一份 `index.html` 200，且 `#fragment` 根本不发给服务器；阶段 1 / 5 必须用 `verify_phase_gates.cjs links` 检查渲染态 DOM（主根互斥 + 幂等 + 入口按钮隔离）。阶段 5 的「深链可达率 100%」只能由这个断言采集。
- **「骨架态页高 = 真实态页高」只证明占位尺寸对齐，不等于线上 CLS = 0**。真实站点的 CLS 来自 34 个 JSON 分批异步到达的时间轴位移，必须按 05 册 4.3 用 `PerformanceObserver`（`layout-shift`，加载后 5s 窗口）在四档视口实测；方案目标是 **≤0.10**，现行基线 0.174。
- **原型视觉稿用的是硬编码示例数据**（少量表格行、预置数值），1883 / 3170 / 溢出 0 是布局契约的验证，不是接上 34 个 JSON 后的真实页高承诺。真实 4957px 研报正文、28 张表共 288 行（含回测明细，明细真实行数未测定）、533px 双轨表进抽屉/折叠后需按 05 册阶段 3–4 复测。
- 04 册映射表中 `#orderForm` 由 `paper_ui.js` 运行时创建、不在静态 `index.html`；`renderAuditPanel` 真实写入的是 `#briefAudit`。原表多写的 `#auditPanel` 别名已删除（真实代码中 0 次出现）。映射表 45 个 render 函数、77 个 id 锚点均已逐条对过真实代码。
