## 2. P1（阻断）：导出菜单 10 项，缺 2 个合并项

### 现象
CDP DOM 实测 `#sExportMenu [data-ds]` = **10 项**（daily/hot/themes/industry/breadth/seats/global/lhb/crosscheck/dirty），全部 `empty:true`（「暂无数据」，因独立页无 `__exportCtx`）。缺生产菜单应有的：
- `data-ds="__csv"` 全部导出（CSV 单表）
- `data-ds="__xls"` 全部导出（Excel 多表页）

V4-3 要求 12 项 = DATASETS 10 + 2 合并项（18 册 §1 已确认此口径）。**当前 10 项不达标。**

### 根因（精确到行）
生产 `app.js:5575-5595` 的 `renderExportMenu()`：
```js
const list = M.exportManifest(exportCtx());     // 返回 10 个数据集
const items = list.map(...);                    // 10 项
menu.innerHTML = hint + items + sep
  + `<button data-ds="__csv">…</button>`         // L5591 手动追加第 11 项
  + `<button data-ds="__xls">…</button>`;        // L5593 手动追加第 12 项
```
即 `__csv`/`__xls` 是 **app.js 在 manifest 结果之外手动追加的**，不属于 `exportManifest()` 的返回值。

而 `s-print.js:55-75` 的 `renderMenu()`：
```js
if (M && typeof M.exportManifest === 'function') {
  let list;
  try { list = M.exportManifest(window.__exportCtx || {}); } catch (_) { list = null; }
  if (Array.isArray(list) && list.length) {
    menu.innerHTML = menuItems(list.map(...));   // L67-69：只渲染 manifest 的 10 项，直接 return
    return;                                     // ← 永远不会走到 FALLBACK 的 12 项
  }
}
menu.innerHTML = menuItems(FALLBACK.map(...));   // L74：FALLBACK 才是 12 项，但只在 manifest 为空时才触发
```
独立页 `window.DatasetExport` 已就绪、`exportManifest({})` 返回 10 项（非空），命中 L66 的 `if` 直接 return → **FALLBACK 的 12 项分支永远走不到**。CodeBuddy 上轮说"FALLBACK 精确列全 12 项"没错，但没意识到运行时代理引擎已就绪会绕过它。

### 精确补丁（照生产 app.js 口径，最小改动）
在 `s-print.js` 的 `renderMenu()` 的 `if (Array.isArray(list) && list.length)` 分支内，`menu.innerHTML = menuItems(...)` 之后、`return` 之前，追加两个合并项，与生产同源：

```js
      if (Array.isArray(list) && list.length) {
        const allEmpty = list.every((x) => x.empty);
        menu.innerHTML = menuItems(list.map((x) => ({
          id: x.id, label: x.label, count: x.count != null ? (x.count + ' 行') : '', empty: !!x.empty,
        })))
          + '<button type="button" role="menuitem" data-ds="__csv"' + (allEmpty ? ' disabled' : '') + '>'
          + '<span class="exp-lab">全部导出（CSV 单表）</span><span class="exp-num muted">合并版</span></button>'
          + '<button type="button" role="menuitem" data-ds="__xls"' + (allEmpty ? ' disabled' : '') + '>'
          + '<span class="exp-lab">全部导出（Excel 多表页）</span><span class="exp-num muted">.xls</span></button>';
        return;
      }
```

要点：
- `allEmpty = list.every(x => x.empty)` 与生产 L5591/5593 的 disabled 判定一致（独立页无 ctx → 全 empty → 两合并项也 disabled，符合"独立页不支持下载"的如实降级）。
- **不要**改 FALLBACK（它本身已是 12 项，只是运行时走不到，保留作为引擎未就绪时的兜底）。
- 文案/类名照抄生产 L5591-5594，避免与屏幕菜单分叉。

### 为什么这不是放水
- 18 册 §1、05 册阶段 4、V4-3 权威口径都是 12 项，生产 app.js 实测也是 12 项——10 项是 s-print.js 移植时的真实遗漏。
- 补丁只改 s-print.js 的 renderMenu，不碰取数逻辑（合并项只是 button 节点，导出动作仍走 §5.1 的如实降级），符合"前端不写取数逻辑"纪律。
