## 4. 真问题：首帧约 2.5 秒显示「未生成」与错误口径数值

`verify_phase2_timing.cjs`：预热后等 `window.__lastArc` 到达，从那一刻起密集采样，**全程不写任何 DOM**。

| 时刻（arc+） | `signals` | `#sKpiRegime` | `#sKpiBreadth` | `#breadthPanel` 已渲染 | `#sKpiScore` |
|---|---|---|---|---|---|
| 0ms | false | **未生成** | **755 / 4472** | 否 | 38.4 |
| +300ms | false | 未生成 | 755 / 4472 | 否 | 38.4 |
| +800ms | false | 未生成 | 755 / 4472 | 否 | 38.4 |
| +1500ms | **true** (`ice`) | 未生成 | 755 / 4472 | **是**（2 条） | 38.4 |
| +2500ms | true | **冰点** | **744 / 4415** | 是 | 38.4 |
| +4000ms ~ +18000ms | true | 冰点 | 744 / 4415 | 是 | 38.4 |

**结论**：
- `warmup_ready_ms:4307`、`arc_arrival_ms:9345`（禁用缓存全量回源），signals 比 arc 晚约 1.5 秒、完全同步再晚约 1 秒。
- 首屏首行 `#sVerdictSub` 在头 2.5 秒会写 `市场状态 未生成`；05 册 L125 要求「首屏首行出现 38.4、6 个 KPI 与旧视图逐字一致」，**首帧不成立**。
- `#sKpiBreadth` 发生**口径跳变**：`755 / 4472`（`__lastArc.summary`，全市场）→ `744 / 4415`（`#breadthPanel`「沪深两市·不含北交所」）。根因是 `readKpis()` 的「DOM 优先、`summary` 兜底」在 DOM 尚未渲染时用了**不同口径**的数据兜底。
- `score_matches_old_all_samples:true` —— V2-1 在整个窗口内始终成立，只有 regime / breadth 两项受影响。
- 会自愈（`regime_auto_corrected:true`、`regime_stuck_unknown:false`），所以是 **P1 而非白屏级 P0**；但慢网/冷缓存下用户会看到一次明显的数值闪变。

**修复建议（二选一，改动都在 `s-page-overview.js`）**：

```js
// A（推荐）：DOM 未就绪时用占位，不用不同口径的数据兜底
// readKpis() 里 breadth：bwUp/bwDn 缺失时返回 '加载中…' 而非 sm.up_count/sm.down_count；
// regime：window.__signals 未到时返回 '加载中…' 而非 '未生成'。
// 并把 #breadthPanel（在 #preMainPanels，不在 #zone-overview）也纳入 observer：
const bp = document.getElementById('breadthPanel');
if (bp) observer.observe(bp, { childList: true, subtree: true, characterData: true });

// B：数据全部到齐前不渲染 KPI 卡，只显示 s-skeleton 骨架（见 §7.3），到齐后一次性替换。
//     这样也顺带满足 05 册 L125「骨架替换位移 0」。
```

另外 `window.__signals` 的到达不是 `#zone-overview` 的 mutation；实测是靠后续其他 render 间接触发的，**属于偶然同步**。建议显式监听：给 `window.__signals` 加 setter 拦截，或在 `sync()` 里做短轮询直到 `signals` 到位，别依赖别人的 DOM 副作用。

## 9. 验收方法学备注（避免复跑时误判）

1. **必须预热导航**。`sw.js` 外壳 cache-first + `cacheKeyOf` 剥 query，首次整页导航会命中旧外壳；本次实测出现过一次「`sKeys:[]` / `sRoot:null` / 页面是静态占位」的空取样（10 册 §5 同一现象）。两个新脚本都内置 `Network.setCacheDisabled` + 唯一 query + 预热；主脚本还加了「未就绪自动重试导航」。
2. **必须轮询等数据，不能用固定 sleep**。禁用缓存后 516KB `bundle.js` + 34 个 `data/*.json` 全量回源，实测 `warmup_ready_ms:4307`、`arc_arrival_ms:9345`、主探针 `readyMs:12216`。固定 3 秒取样会拿到 `--` 占位。
3. **判定要用相对量**：`sRootOffsetHeight===0`、V2-1 文本比对、`contribution.delta===0`；不要用 `bodyScrollHeight` 绝对值（本次在 7694~9539 之间随数据刷新波动）。
4. 本会话 Windows 工作区无真实仓库，`npm test` / lint / `.lighthouse/baseline.json` 采信 CodeBuddy 侧结论；本轮只读线上，未提交、未推送、未改任何线上文件。
