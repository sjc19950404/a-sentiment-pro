## 2. 纠正：`drawer.ok` 的真实门禁比 CodeBuddy 说的窄

线上 `s-selftest.js` L206 原文：

```js
out.ok = !drawer.hidden === false && drawer.hidden === true && document.activeElement === before;
```

- 前两项 `!drawer.hidden === false` 与 `drawer.hidden === true` **语义重复**，都等价于 `drawer.hidden === true`。
- 真正门槛只有两条：**ESC 后 `drawer.hidden === true`** 且 **焦点回到打开前的元素**。
- CodeBuddy 描述的「打开后焦点在抽屉内、`aria-modal=true`」只是 L200–L201 写入 `out.steps` 的**观察字段，不参与 `out.ok`**。

由此产生两条必须写进验收的防假绿要求：

1. **不许走 fallback 分支**：L188 的 `if (!S || typeof S.openDrawer !== 'function')` 分支只要求 `aria-modal="true"` + `role="dialog"` 就返回 `ok=true`。只把静态节点塞进页面、不实现 `S.openDrawer`，自检照样绿。验收必须断言 `typeof S.openDrawer === 'function'` 且走的是动态路径（`drawer.steps` 应包含 `hidden after open = false`）。
2. **不许空实现骗绿**：若 `S.openDrawer` 什么都不做、抽屉初始 `hidden=true`，则 ESC 后 `hidden` 仍为 true、焦点未移动 → `out.ok=true`。所以验收必须用 CDP 真看**打开态**和**关闭态**，不能只看 `runSelfTest().drawer.ok`。

另外两个实现硬约束：

- **ESC 监听必须挂在 `document`**：自检用 `document.dispatchEvent(new KeyboardEvent('keydown',{key:'Escape',bubbles:true}))`，挂在抽屉元素上的监听收不到（04 册 L1256 的伪代码正是挂 `document`，照抄即可）。
- **关闭动画与等待窗口仅 80ms 余量**：04 册 L1243 `setTimeout(finish, 200)`；自检 L203 `await wait(280)`。`finish()` 在 200ms 才写 `hidden=true` 并还焦点，必须在真实负载下多跑几次确认 280ms 内落地；必要时把动画缩到 ≤160ms，或保留 L1240 的 reduced-motion 同步分支。

## 3. 实证：JS 注入的两种坑，以及正确修法

诊断脚本 `design/verify_phase4_drawer_scope.cjs` 用线上 CSS 在 CDP 里跑了三种注入方式，结果存于 `design/assets/阶段4抽屉作用域诊断.json`：

| 注入方式 | `hidden=true` 时 `.s-drawer` computed display | 现象 | 判定 |
|---|---|---|---|
| 裸挂 `body`，**无**定向规则 | **`flex`** | 作者样式 `.s-drawer{display:flex}` 覆盖 UA `[hidden]{display:none}`；只靠 `opacity:0;transform:translateX(100%)` 视觉隐藏 | ❌ 非真隐藏；`focusables()` 按 `offsetWidth>0` 仍能看到子元素，焦点陷阱/a11y 有隐患；自检只看属性会假绿 |
| 包一层 `.s-scope` | `none` | `[hidden]` 生效，但 `.s-scope{min-height:100dvh;background:var(--s-bg-0)}`（tokens L209–213）让这层**不透明铺满整屏**；探针 `elementAtCenter: sDrawerLayer` 实证它会盖住研报 | ❌ 会在默认研报视图黑屏遮页，除非再补 `min-height:0;background:none` 两条覆盖 |
| 裸挂 `body` **+ 定向 `[hidden]` 规则** | `none` | 真隐藏；去掉 `hidden` 后回到 `flex` 且子元素可聚焦 | ✅ **推荐** |

补充事实：

- 遮罩 `.s-drawer__mask` 本身没问题——它没有作者 `display`，UA `[hidden]` 生效，三种方式下 computed display 都是 `none`，不存在「遮罩拦截整页点击」。
- `s-components.css` L38–L40 的注释「不用全局 `[hidden]{display:none!important}`」针对的是**全局**规则会牵动研报十几处面板；**定向规则只作用于这两个 id，不触发该顾虑**。

## 4. 裁定

### 决策 1：同意 JS 注入，但附一条强制前置条件

**同意**「JS 注入抽屉、不改 index.html 的 DOM 结构」，理由：

- `.s-drawer` / `.s-drawer__mask` 是全局选择器，注入到 body 能命中全部样式、三档宽度和 `<640` 全屏 sheet。
- `checkDrawerFocusTrap` 在调用时用 `getElementById` 取节点，注入时机只要早于自检即可。
- 与阶段 2/3 一样，新增文件走标准白名单即可，不引入新的部署机制。

**但必须同时满足以下四条，否则否决**（这是本轮唯一的硬修正）：

1. `s-drawer.js` 必须在 `s-components.css` **之后**加载，并向 `document.body` 注入 `04 册` L170–L186 的**完整节点集**（`#sDrawerMask`、`#sDrawer`、`#sDrawerGrab`、`#sDrawerTitle`、`#sDrawerSub`、`#sDrawerClose`、`#sDrawerBody`、`#sDrawerDone`、`#sTooltip`），不能只注入两个空壳。
2. **补一条定向 CSS 规则**（放 `s-components.css` 抽屉段）：

   ```css
   /* 裸 body 注入时 .s-drawer{display:flex} 会盖过 UA [hidden]，定向兜底；
      只作用于这两个节点，不碰研报面板 */
   .s-drawer[hidden], .s-drawer__mask[hidden] { display: none !important; }
   ```

   `!important` 与 `tokens.css` 的 `.s-scope [hidden]` 口径一致；即便不加，`(0,2,0)` 也胜过 `.s-drawer` 的 `(0,1,0)`，但保留更稳。
3. **不要**把注入节点包进 `.s-scope`，也不要塞进 `#sRoot`：前者铺满不透明背景盖住研报（§3 实证），后者在阶段 5 前的默认研报视图里是 `hidden` 的，焦点无法进入，造成假绿。
4. 仍需在 `index.html` 加**一个 `<script src="s-drawer.js" defer>`**（放在 `s-root.js` 之后），并同步**四处白名单**：
   - `index.html` L46 后新增 script 标签
   - `.github/workflows/deploy-pages.yml` `paths`（L79–L87 段）与 `cp` 行（L132）
   - `sw.js` `SHELL_ASSETS`（L57–L65 段）
   - `src/offline.js`（L65–L73 段）

> 「不改 index.html 结构」按「不加抽屉 DOM 节点」理解；script 标签和 CSS 规则不属于结构改动。

### 决策 2：同意拆 4a / 4b，但 4b 不得移出阶段 4

**同意**本轮只做 4a（抽屉），打印页放 4b。理由：

- `drawer.ok` 是阶段 5 硬门槛的关键路径，应先单独解锁并验收。
- 打印页是独立路由，有自己的白名单、`@media print` 规则和跨页表头要求（04 册 L649），混在一轮会放大回归面。
- 与阶段 2「收口」、阶段 3「架构裁定→实现→验收」的既定节奏一致。

**约束**：4b 仍属阶段 4，不得改名、不得顺延到阶段 5，也不得不上线。4a 收口时须在交接里明确写出 4b 的范围与验收标准。

## 5. 阶段 4a 准出门禁（CDP 实证，不只看 `runSelfTest().drawer.ok`）

1. **作用域**：`#sDrawer` / `#sDrawerMask` 存在于 body、不在 `#sRoot` 内；`hidden=true` 时 computed display 必须是 `none`。
2. **动态路径**：`typeof S.openDrawer === 'function'`；自检 `drawer.steps` 含 `hidden after open = false`（证明没走 L188 的静态 fallback）。
3. **打开态**：`hidden=false`、`.is-open` 已加、`aria-hidden="false"`、`aria-modal="true"`、`role="dialog"`、`document.activeElement` 在 drawer 内、`document.body.style.overflow === 'hidden'`。
4. **关闭态**：`document` 上派发 ESC 后 280ms 内，`hidden=true`、`.is-open` 移除、`aria-hidden="true"`、焦点 `===` 打开前元素、body overflow 还原。
5. **四种关闭路径**：关闭按钮、完成按钮、点遮罩、ESC 都生效。
6. **三档 + 移动端**：桌面 computed width = 420 / 640 / 960px；390px 下抽屉 = 视口宽、`100dvh`、grab 可见、无横向溢出。
7. **焦点陷阱**：Tab / Shift+Tab 在抽屉内循环，不逃出到背景页。
8. **自身全绿**：`runSelfTest().drawer.ok === true`，且其它门禁不退化（横向溢出 0、盒内滚动违规 0、触控违规 0、对比度违规 0、空状态 0/0、`skeletonSwap.pass=true`、CLS ≤ 0.174 或 null）。
9. **默认研报零变化**：默认视图下 `main` 可见且贴顶、`#sRoot` 真隐藏、旧 UI 未变、fatalHolder 零触发、console exception 0。
10. **白名单**：四处同步（§4 决策 1 第 4 条），线上 `s-drawer.js` 可 200 且内容新鲜。

只有 1–10 全绿，才允许 CodeBuddy 进入 4b。
