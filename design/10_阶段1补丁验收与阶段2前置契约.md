## 5. 为什么第一次跑是 20/21：首导航缓存滞后（P1，非阻断）

同一份代码，**未预热**时门禁是 **20/21**（唯一 FAIL：默认 `/` 影子根 `display:flex / 874px`），回归 verdict 里 `workbench_rootAtTop` / `workbench_noOldUi` / `popstate_hides_sRoot` 三项 false。预热后全部转绿。

成因链（已逐环节核实）：

1. `deploy.yml:143-150` 每次部署向产物 `site/sw.js` 注入 `CACHE_VERSION='v2-<GITHUB_SHA::7>'`，本次是 `v2-3425bc1`（03:30 的 data 提交，晚于 `28614dee` 03:19）。
2. `sw.js` 外壳走 **cache-first**（`strategyFor` → `SHELL_CACHE`），且 `cacheKeyOf` 执行 `u.search = ''` **剥掉 query**。
3. 因此 `?_cb=<ts>` 对 SW 缓存键无效；`Network.setCacheDisabled` 只管 HTTP 缓存，**管不到 SW 的 CacheStorage**。首次整页导航由旧 SW 供给旧 `style.css` / `s-components.css`。
4. 新 SW `install` 里 `skipWaiting()` + `activate` 里 `staleCaches` 清旧缓存 + `clients.claim()`；`index.html:1481` 的 `controllerchange` 在**已有旧 SW 控制**（`hadController=true`）时自动 `location.reload()`。第二次导航起才稳定拿到本次部署资源。

实证（同一浏览器实例内，回归探针 5 个用例）：

| 用例序号 | 资源版本 | `rectTop` | `hidden 时 display` | `bodyScrollHeight` |
|---|---|---|---|---|
| 1 `?view=workbench`（首次） | 旧 | 180 | `flex` | 1054 |
| 2 同页 popstate（同一旧文档） | 旧 | 9539 | `flex` | 10413 |
| 3 默认 `/`（整页导航） | **新** | 0 | `none` | 9539 |
| 4 `?view=terminal` | **新** | 0 | `none` | 9539 |
| 5 `?view=workbench` | **新** | 0 | — | 874 |

**对真实用户的影响**：已注册 SW 的旧标签页在部署后首次访问仍会短暂看到旧布局（研报页底一屏空白 / workbench 不贴顶），靠 `controllerchange` 自动 reload 或手动刷新一次即恢复。这是既有 SW 机制，不是本轮补丁引入的缺陷，也不阻断阶段 1 验收；但**验收脚本必须预热**，否则每次部署后第一次跑门禁都会假红。

## 7. 进阶段 2 前必须钉死的 5 条契约

阶段 1 的地基已经干净，但下面 5 条在 05/06 册里没有一致答案，动手前必须先定，否则「白屏无法归因」会重演。

### 7.1 【最高】搬 DOM 还是 clone？回默认视图时怎么还回去？

- 06 册 L104 写「**搬迁** `#emScore` 等结论层节点到 `.s-page-overview`」；05 册 L124 同时写「研报视图与终端视图**不受影响**」。
- 但阶段 5 前**默认仍是研报视图**，而 `#emScore`(L989) / `#btStrategyPanel`(L968) / `#btNavSvg`(L1093) 都在 `<main>` 里。真 `appendChild` 搬走，默认研报视图就少一块 KPI —— 与「不受影响」直接冲突。
- `s-root.js` 的 `route()` 恢复分支只做 `main.hidden=false`，**没有节点还回逻辑**。
- 建议契约（二选一，写进 06 册再动手）：
  - **A（推荐）**：工作台激活时 `cloneNode(true)` + 由 `MutationObserver` 同步数据，旧节点原位不动；回默认不清理，天然幂等。代价是数值双份、需保证同步。
  - **B**：只在 workbench 激活时搬走，`route()` 回默认前按 `data-s-origin` 记录的原父节点/nextSibling 精确还回，并在「二次进入幂等」门禁里加断言。
- 无论哪种，都要把「默认研报视图 6 个 KPI 逐字不变」列成阶段 2 的独立门禁（当前 05 册 V2-1 只比 `#sKpiScore` 与 `#emScore`，没查旧视图是否还在）。

### 7.2 骨架里没有目标容器与断言锚点

`s-root.js` 的 `buildShell()` 现在只有 `s-ph-*` 占位（`s-ph-topbar` / `s-ph-main` / `s-ph-panel` / `s-ph-tab` / `s-ph-title`），**没有**：

- `.s-page-overview` → 06 册 L113 的 `document.querySelector('.s-page-overview #emScore')` 在阶段 1 恒 false；
- `#sKpiScore` → 05 册 L131 V2-1 数值一致性断言的两端缺一端。

`s-page-overview.js` 必须同时负责建容器与两个锚点，不能假设它们已存在。

### 7.3 CLS 放行口径在 05 册内部冲突

- 05 册 **L125**（阶段 2 上线条件）：`CLS <= 0.10`；
- 05 册 **L722**（5.2.1 评审修订）：「灰度期允许 `pass:false` 且 `degraded:false`，**阶段 5** 翻默认视图前必须 `pass:true`」；
- 阶段 0 实测同页同视口两次 CLS **0.112 → 0.1593**（波动 42%，均 `pass:false / degraded:false`）。

按 L125，阶段 2 现在就过不了；按 L722，阶段 2 可以放行。**必须先统一**：建议阶段 2 按「不劣于基线 0.174」判，`≤0.10` 留到阶段 5；并采纳 09 册建议，四档各 ≥3 次采样、取中位数且最差值达标，单次采样不作放行依据。

### 7.4 幂等重搬的触发源要指名

06 册 L108 的验收表达式是 `renderEmotion(LATEST); renderBreadth(BREADTH);` 后断言节点仍在新根。但 `app.js` 的 render 由 `data/*.json` 分批到达驱动，工作台激活时 `<main>` 是 `display:none`——**`display:none` 子树里的 render 是否仍会触发 `innerHTML` 覆盖**，需要一个显式触发源说明（在 `s-page-overview.js` 里主动调一次，还是监听旧容器 mutation）。这直接决定「第二帧回到旧布局」能不能被测到。

### 7.5 canvas re-init 严格留到阶段 3

`LW.createChart` 在 `app.js:684` / `:2212`（研报视图），终端视图全是 SVG（已核实）。阶段 2 不要碰 `#btNavSvg` 的图表实例；阶段 3 再按 06 册 L167「白屏②」处理。
