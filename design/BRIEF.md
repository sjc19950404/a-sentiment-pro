> 不是需求清单推测。**禁止引用已被证伪的旧结论**（见文末）。

站点：https://sjc19950404.github.io/a-sentiment-pro/

## 1. 系统现状：两套 UI 并存

### A. 研报视图（当前默认主视图，style.css 141KB）
- `index.html` 238KB / 3414 行；194 个 id、38 section、28 张表、288 行、28 个 `<details>`。
- 外链资源仅 `style.css` / `app.js`(377KB) / `bundle.js`(516KB) / `vendor/lightweight-charts`。
- 数据层：34 个 `data/*.json` 实测可达，54 个 `function render*`（app.js 38 + bundle.js 17，去重后 54），**模块边界清楚，可只动展示层**。

### B. 研究工作台（终端视图，`?view=terminal` 或 `#terminal` 深链）
- **不是独立页面**：`index.html` 内联的全屏覆盖层，40KB CSS（第 40–723 行）+ 生成物 JS，
  挂载 `#tRoot.t-scope`，所有选择器 `.t-` 前缀，与研报视图零耦合。
- 入口：`⚡ 图表终端`，`position:fixed; top:8px; right:12px`；返回用终端顶栏「📄 研报」。
- 顶栏常驻：已收盘 / 数据日 / regime 序列 90 日 / 时间窗 20·30·60·90 / 当前 regime。
- 8 个 tab：总览 · 涨跌停 · 资金 · 板块 · 选股 · 模拟盘 · K线 · 系统设置；底部 ticker。
- 12 列栅格 `t-c12 / t-c8 / t-c6 / t-c4`；`.t-main` 实测 `overflowY: visible` —— **整页滚动、零盒内滚动**。
- 总览首屏 = 一行 6 个核心指标（38.4 / 冰点 / 执行仓位 0~20% / 涨停37·跌停33 /
  涨跌家数 755·4472 / 龙虎净买 -0.77亿）→ 60 日情绪分走势大图 → 七因子环形仪表 →
  regime 分布 → 主线题材 → ETF 对冲卡（待命态，红利低波510880 / 沪深300510300 / cap=0.2）。
  **这是「结论层 → 证据层」的正确组织，正是研报视图缺的。**
- 有 `LINK` 跨视图联动总线、时间窗切换、tooltip、工作台自己的 `.t-` 抽屉。
- **8 个 tab 中 6 个是完整功能**。K线输入 600000 后渲染 664 根日K（蜡烛+三均线+成交量+
  hover 十字+周期下拉）；系统设置有 5 个参数滑块 + 沙盒推演结果区；选股天梯行下钻会打开
  内含盘口/逻辑推演/GLM 命中率/持仓/内嵌 K线的抽屉。稀疏的只有模拟盘（账户确实空仓）
  与资金（代码明确「三方数据未产出 → 不伪造」）。

### C. 已有的设计纪律（内联 CSS 注释，必须继承，不要另造第三套）
「chrome 柔、数据锐」；辉光只允许三处（选中细边光 / 警报呼吸 / 主图当前值微光点）；
动画只做 opacity/transform；尊重 `prefers-reduced-motion`；不用 `backdrop-filter`（树莓派掉帧）；
深色磨砂黑 + 青色主色；红涨绿跌（中国 A 股约定）。

## 3. 真实存在的问题（去掉观察方法造成的假象后仍成立）

### 3.1 信息架构：没有分层 —— 根因
14 类功能被当作 14 个平级容器顺序平铺，缺「结论层 / 证据层 / 操作层」。
宏观长图是等宽、等距、等密度的深色条块，没有阅读起点，也没有视觉焦点。这就是「大杂烩」的来源。

### 3.2 权重倒置
模拟盘 36% + 回测 22% = **58% 屏幕给操作/审计**；回答「今天盘面有什么风险」的
告警 + 概览只有 **17%**。全站唯一大字 `38.4` 出现在第 459px，前面被 13 条平级告警堵着。
一个分析辅助工具，把最多的屏幕给了交易台。

### 3.3 CLS 治理反噬可用性（style.css:1299 起有站点第四轮实证注释）
- 基线桌面 CLS **1.281** / 移动 **1.391**。现行方案：把 13 个状态面板 + `#alerts` 塞进
  `#preMainPanels` 恒定高容器（桌面 22rem / 窄屏 26rem），每个面板锁死 `height/min/max:3rem`
  + `overflow-y:auto`；首屏 `.grid>.card` 锁 22rem 盒内滚动；`header.topbar` 锁 64px。
  CLS 降到 **0.174**。
- 代价：13 个平级面板被压成等高条带，无主次分组；折行后**半截字裁切**；
  容器滚 + 面板滚 + 卡片滚 = **盒中盒滚动**（全页共 18 处盒内滚动容器）。
- 残余 CLS 0.174 拆解：0.128 来自 `btStrategyPanel` 骨架→真实表格盒内替换，
  0.046 来自 `mom-group`。
- **已证伪、切勿重复建议**：逐个给面板加 min-height（CLS 逐位不变）、关 smooth/overflow-anchor、
  main 加 contain、给 main 固定高、把 btStrategyPanel 放大到 26rem（0.802→0.890 反而变差）、
  去掉高度上限。注释明确 18rem「不得再调大或去掉」。
- 正确方向：**用骨架占位（skeleton，尺寸与真实内容一致） + 内容原位替换**替代「锁死高度 +
  盒内滚动」，同时解决 CLS 与裁切，不依赖把 CLS 当硬约束。

### 3.4 移动端是主战场
- 390px 整页 **34829px**（桌面 3.7 倍）/ 43 屏；`zone-backtest` 单区 **12440px**，
  `zone-brief` 7933px。
- 11 个状态面板 client 高仅 **48px**；`reportPanel` 实际内容 **4957px**（露出约 1%），
  `breadthPanel` 968px、`dualTrackPanel` 827px；`card momentum` 1323px 塞进 382px。
- 导航锚点 right=479 溢出 390；双轨 `dt-table` 宽 533 / right=546 横向溢出；
  标题折成「批量下/单」；固定「横屏视图」按钮遮挡表单；顶栏快捷键说明与导出按钮被裁出视口。

### 3.5 其余
- 空状态无设计：「今日无主线标的」占整卡 60% 空白；持仓 / 待成交 / 成交记录 / 事件日志
  四表全「暂无…」，每张仍占满完整卡片高度。
- 全站字号几乎一档（研报正文 / 行情表 / 日志 / 口径 / 免责同级），靠颜色区分而非字级层级。
- sticky 顶栏 + 左下「横屏视图」+ 右下「↑」在 9 屏里逐屏重复。
- 详情抽屉（研报视图 `#drawer`）是全站**唯一层级清晰的容器**：921 字分 5 组、键值对齐、
  红绿占比条、自带滚动。但**仅 520px 宽**，席位名截成「深股…」「机构…」，
  装数百行回测明细需加宽 / 全屏变体。
- 布局塌陷：内容少的视图（K线空态 / 系统设置 / 资金）底部 ticker 飘到页面中部 y≈245，下方大片纯黑。
- 跨视图 tooltip 残留：K线切到系统设置后 hover 黑框仍留左下角。
- 「载入完整档」点击后变「载入中…」，6 秒后仍如此，行数与高度不变，既不完成也不报错。
- 刷新反馈弱（DOM 文字更新但视觉几乎看不到）；`#verTable` 行点了没反应（其余 4/5 抽屉入口可用）。
- `-` 键是 30 日精简档 ↔ 265 日完整档的**数据范围切换**，不是布局切换。

### 3.6 已验证可用的交互资产（不要推翻）
时间窗 20/60/90 实时改图；tooltip；`/` 聚焦搜索；`1-6` 跳分区；研报 10 章导航；
导出菜单 12 项带行数标注；`<details>` 折叠（11–12 个）；抽屉 4/5 入口；
刷新回「已是最新」；ETF 对冲卡；工作台联动下钻。

## 4. 已证伪的旧结论 —— **禁止再引用**

1. ❌「K线 tab 几乎全空是半成品」→ ✅ 未输入代码时的默认态，输入后完整渲染。
2. ❌「系统设置只有两个按钮」→ ✅ 5 个参数滑块 + 沙盒推演结果区（当时等待 1.5s 不够）。
3. ❌「回测指标表列头与数据分在两屏」→ ✅ 是 1100px 分段截图的边界假象，页面本身连续。
4. ❌「工作台联动下钻没复现」→ ✅ 有 `.t-` 专属抽屉，比研报抽屉更丰富。
5. ❌「ETF 对冲卡没找到」→ ✅ 在总览 tab，「待命」是业务状态。
6. ❌「主界面没有工作台切换入口」→ ✅ 入口是 `position:fixed` 的 `⚡ 图表终端`
   （`offsetParent` 恒为 null，是当时可见性检测方法错了）。
7. ❌「资金 tab 没做」→ ✅ 代码明确「三方数据未产出 → 不伪造」。
