## 3. 事实纠正：方案 A 的前提不成立

### 3.1 生产 `index.html` **有** `<main>`，而且包住了整个研报 SPA

```
_cb3_index.html:978   <main>
_cb3_index.html:1425  </main>
```

- `grep -c '<main'` = **5**，其中 4 处是注释文字（L874/875/967/971），**1 处是真标签 L978**。CodeBuddy 大概率把注释命中与真标签混在一起，或搜的是带属性的写法。
- 978–1425 共 448 行，内含 `zone-overview` 起到 `zone-paper` 的全部 zone，`hotTable`(L1072) / `hotHead`(L1073) / `btNavSvg`(L1093) 都在里面。
- `app.js:434` 与 `app.js:452` 的 `document.querySelector('main')` **能取到**，是 fatal 兜底流程（`app.js:445` set / `app.js:453` remove `aria-hidden`），不是恒 null。
- `<main>` 之外只有 `#preMainPanels`(L880)、`#fatalHolder`(L975)、`#tRoot`(L1535)、`#drawer`(L1435) 等少数浮层 —— 这与 `index.html:971` 的注释「刻意放在 `<main>` 之外」完全一致。

所以「研报视图是散落在 body 的静态标记、不是一棵可整体搬的子树」不成立：**绝大多数研报 DOM 就在 `<main>` 这棵子树里**。

### 3.2 R2 默认用例实跑是 PASS，不是 `none`

修探针前后两次实跑，默认 `/` 都是：

```json
{"got":"report","activeRoots":[],"mainVisible":true,"mainAriaHidden":false}
```

`mainVisible:true` → `got:"report"` → PASS。CodeBuddy 说的「`mainVisible` 恒 false → 默认用例判 `none` → 无论搬不搬都得包一层 `<main>`」，**被实跑直接推翻**。

> 反向风险：真按方案 A 再包一层 `<main id="app">`，会造成**双 `<main>` 嵌套**（HTML 语义违规），且 `document.querySelector('main')` 会取到新包的外层，破坏 `app.js` 的 fatal 兜底逻辑。这一步不但不需要，而且有害。

### 3.3 `terminal.js` 线上 404：源码与线上产物不是同一份

- 仓库根有 `terminal.js`（130836 bytes），但 `deploy-pages.yml:128` 的固定 `cp` 清单**不含** `terminal.js` → 线上 `https://sjc19950404.github.io/a-sentiment-pro/terminal.js` **404**。
- 线上跑的是 `scripts/build_terminal_inline.mjs` 内联进 `index.html` 的副本（L1540 起、L3248 `root.className='t-scope'`、L3391 入口按钮）。
- 因此 CodeBuddy 引的 `terminal.js:1707/1724/1879` 是**仓库源码行号**，线上没有这个独立文件。结论（SVG 图表、mount 一次）本身没错，但**任何终端改动必须源 + 内联副本两处同步**，否则下次 rebuild 会被覆盖 —— 这次 R3 恰好两处都改了。

## 4. 架构纠正：「重搬」的对象、时机、目标根

### 4.1 05/06 册的权威口径（原文）

| 出处 | 原文要点 |
|---|---|
| `05_落地实施与验收.md` L16（机制 A） | `s-adapter.js` 用 `MutationObserver` 观察**既有 render 的产出节点**，把节点 `appendChild` / `replaceChildren` **移动到 `.s-*` 容器**；「移动节点不触发重新计算、不读 JSON、不调用 render」 |
| `05` L96（阶段 1） | `s-adapter.js` 只是「**LINK 订阅 + MutationObserver 骨架**」；shell 由 `s-mount.js` 渲染 8 tab 路由 / ticker / tooltip 单例 |
| `05` L123（阶段 2） | `s-page-overview.js` 把 `renderEmotion` / `renderRegime` / … 的产出**搬入 1.2 骨架** |
| `05` L146（阶段 3） | `s-table.js` / `s-page-backtest.js` / `s-page-zt.js` 做分页与表格治理 |
| `06` L104 / L113 | 搬迁 `#emScore` 等**结论层节点到 `.s-page-overview`**；验收断言 `document.querySelector('.s-page-overview #emScore')` |
| `06` L137 | 搬动含 LW canvas 的**净值曲线**节点后图表 re-init 成功 |
| `04` L83 起 | 工作台是**全新搭建**的 `<div class="s-scope s-app" id="sRoot">` shell（topbar / nav / 8 tab / 骨架） |

**一句话**：新工作台 shell 自己搭，旧 render 产出的**具体数据节点**被搬进新 shell 里的一个个 `.s-*` 组件容器复用。工作台和研报视图是**互斥的两个视图**（`activeRoots` 唯一），不是一个吞掉另一个。

### 4.2 CodeBuddy 的三重误读

| # | 它的说法 | 实际 |
|---|---|---|
| ① 对象 | 「把整个研报 `<main>` 搬进 `#sRoot.s-scope`」 | 搬的是 `#emScore` / `#btStrategyPanel` / 净值曲线等**单个数据节点**，目标是 `.s-page-overview` 等**组件容器**；不是把视图 A 塞进视图 B |
| ② 时机 | 「阶段 1 的幂等重搬 + canvas re-init 真正作用于研报视图」 | 白屏①幂等重搬是**阶段 2**（`s-page-overview.js`）、白屏② canvas re-init 是**阶段 3**（`s-table.js`）；阶段 1 只要 MutationObserver **骨架** |
| ③ 目标根 | 「工作台 = 把研报视图重挂载进 `#sRoot`」 | 工作台根是独立新 shell；把 `<main>` 塞进去会让两个互斥视图合并，`mainVisible` / `activeRoots` / 04 册蓝图全部崩掉，A 方案退化成「研报换个壳」 |

它把「**数据节点复用**」读成了「**视图整体迁移**」，于是才需要「先包一层 `<main id="app">`」这个并不存在的步骤，也才把阶段 2/3 的活提到了阶段 1。

### 4.3 A / B / C 判定（明确，不踢球）

| 选项 | 判定 | 理由 |
|---|---|---|
| **A** 包 `<main id="app">` + 整体搬 + re-init | **否决** | 前提错（`<main>` 已存在）、方向错（互斥视图合并）、破坏 `app.js` fatal 逻辑与 04 册蓝图；且把阶段 2/3 的活提前 |
| **B** 按 04 册在 `#sRoot` 新搭工作台 | **方向正确，但描述要修正为 B′** | CodeBuddy 写的「不复用静态标记」是错的 —— 设计正是要用 `s-adapter` 复用旧 render 产出节点。**B′ = 新搭 shell + 逐组件搬数据节点** |
| **C** 先留骨架、s-adapter 暂缓 | **这才是阶段 1 的正确姿势，不是停滞** | 05 册 L96 明确阶段 1 只需 MutationObserver 骨架；阶段 2 才做幂等重搬 |

**结论：不选 A，也不选 B/C 原样 —— 执行「C 收口 → 阶段 2 走 B′」。**

## 6. 新发现的问题与补丁

### P0-1 · 工作台视图下研报整页没被隐藏（真缺陷，CodeBuddy 未提）

`s-root.js:93` 用 `main.setAttribute('aria-hidden','true')` 隐藏研报，但 `aria-hidden` 在本站是 **fatal 兜底信号**：

- `style.css:1457` `main[aria-hidden="true"] { display: none; }`
- `app.js:445` 设为 true（showFatal）／ `app.js:453` `removeAttribute('aria-hidden')`（hideFatal）

数据加载成功后 `app.js` 的清除函数把 `s-root.js` 设的值一起抹掉 → 实测 `ariaHidden:null`、`display:block`、`visible:true`。**复用了一个会被别人清理、且有独立语义的信号。**

修法：**不要碰 `aria-hidden`**，改用 `[hidden]` + 专用视图 CSS 双保险，并把 `<main>` 之外的旧浮层一并收起。

```js
// s-root.js — route() 替换（只列改动部分）
let hidTRoot = false;
function route(view) {
  const sRoot = $('sRoot');
  const tRoot = $('tRoot');
  const main  = document.querySelector('main');
  const pre   = $('preMainPanels');
  const wantBench = view === 'workbench';

  if (wantBench) {
    document.body.dataset.view = 'workbench';
    if (sRoot) { buildShell(); sRoot.hidden = false; }
    if (tRoot && !tRoot.hidden) { tRoot.hidden = true; hidTRoot = true; }
    if (main) main.hidden = true;          // 不再用 aria-hidden
    if (pre)  pre.hidden  = true;          // <main> 之外的 352px 告警区
  } else {
    delete document.body.dataset.view;
    if (sRoot) sRoot.hidden = true;
    if (main) main.hidden = false;
    if (pre)  pre.hidden  = false;
    // 只恢复「本次由我隐藏」的 tRoot；整页导航时 hidTRoot=false，
    // 不会在默认研报视图误放出终端覆盖层。
    if (hidTRoot && tRoot) { tRoot.hidden = false; hidTRoot = false; }
  }
}
```

```css
/* style.css 追加：显式覆盖，避免任何 main{display:block} 让 [hidden] 失效 */
body[data-view="workbench"] > main,
body[data-view="workbench"] > #preMainPanels { display: none; }
```

配套：R2 的 workbench 用例必须断言 `mainVisible === false`（本册已在本地探针补上）；`#drawer`、`#t-entry` 已有各自隐藏规则，不用重复。

### P1-2 · `#sRoot` 缺 `s-app`，工作台不是全屏根

`components.css:29` 的 `.s-app` 才有 `display:flex; flex-direction:column; min-height:100vh/100dvh; width:100%; overflow-x:clip`，移动端还有 `padding-bottom` 安全区与 `display:block; min-height:0; overflow:visible`（L1058 / L1340）。`s-root.js:105` 只建了 `class="s-scope"` → 这些全部不生效，实测高度只有 874px。

### P1-3 · 骨架不是「可用 shell」

05 册 L98 要求阶段 1「深链能渲染 **8 tab 与空 panel**」、L96 要求 `s-mount.js` 做 **8 tab 路由** / ticker / tooltip 单例；当前 `buildShell()` 给的是 **9 个 `disabled` 按钮** + `cursor:not-allowed` + 一段「骨架已就位」说明文字。且新增 CSS 用 `.s-scope .s-topbar` / `.s-nav` / `.s-main` 与 04 册的组件类**同名不同义**，阶段 2 接真组件会样式互撞。建议：tab 数收到 8、去掉 `disabled` 换成可路由的 `data-page` 锚点、骨架类名改成 `s-ph-*`（placeholder 专用前缀），把 `.s-topbar` 等留给真组件。

### P2-4 · `route()` 恢复分支与监听不完整

- 原 `else` 分支只 `sRoot.hidden = true`，不恢复 `tRoot`（见 P0-1 补丁的 `hidTRoot`）。
- 文件头注释写「`hashchange` / `popstate` 重路由」，但代码**只注册了 `hashchange`**。`?view=workbench` 是 query，SPA 内 `pushState` 改 query 不会触发 `hashchange`。

```js
window.addEventListener('popstate', () => route(parseView() === 'workbench' ? 'workbench' : 'report'));
```

> 现有 R2「二次进入幂等」用的是 `Page.navigate` 整页跳转，**没覆盖 SPA 内切换**，建议补一条同页 `history.pushState` 来回的断言。

### P2-5 · 文件名与 05 册口径不一致

05 册 L95/L96、06 册 L55 写的是 `s-mount.js` + `s-adapter.js` + `s-flags.js` 三个文件；落地是 `s-root.js` 一个文件把路由 / flag / shell 混在一起。功能可行，但阶段 2 按文档找 `s-mount.js` 会扑空。建议补一行文档说明或重命名对齐（07 册 3.1 已出现过同类命名分叉）。

### P2-6 · 06 册 L75 措辞不严谨

表里写 `?view=terminal` 时「`main` 不显示」，实测 `mainVisible:true`（终端 `.t-scope` 是 fixed 全屏覆盖层，把 main **盖住**而非隐藏）。探针的 `got` 优先级使判定仍正确，但表述应改成「`main` 被覆盖层遮挡，不参与 `activeRoots`」。
