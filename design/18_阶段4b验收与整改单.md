## 3. P0 根因（决定性）

**`s-print.js:24` 调用 `S.getFlag('reportV2', true)`，但 `report.html` 没有加载提供 `getFlag` 的 `s-root.js`。**

CDP 抓到的异常（首轮脚本漏采，因未启 Runtime 域；专项诊断补齐）：

```
EXC: TypeError: S.getFlag is not a function
    at enabled (s-print.js:24:33)
    at init (s-print.js:142:10)
    at s-print.js:169:8
```

后果链：

1. `init()` 第一行就抛错 → 整个初始化中断。
2. `S.initPrint` / `S.renderPrintExportMenu` 未挂载 → 线上 `window.S` keys = `[]`（实测）。
3. 三按钮无事件监听：复制全文 / 打印 / 导出菜单开合**全部失效**。
4. 导出菜单 0 项（`#sExportMenu` 永远是空 + hidden）→ V4-3 失败。
5. `window.DatasetExport` 已就绪（object），但 `renderMenu()` 从未被调用，所以 12 项没渲染出来——**不是 exportManifest 的问题，是初始化根本没跑**。

对照：`s-drawer.js` 同样依赖 `S.getFlag`，但它跑在 `index.html`（有 s-root.js），所以阶段 4a 全绿。这是 4b「独立页」这个新场景独有的依赖缺口——CodeBuddy 直接沿用了 4a 的写法，没意识到宿主不同。

## 4. 精确整改补丁（三选一，推荐方案 A）

### 方案 A（推荐，最小改动、零副作用）：`s-print.js` 自带 getFlag 防御兜底

在 `s-print.js` 顶部（IIFE 内、`enabled()` 之前）加：

```js
  // report.html 独立页不引 s-root.js，S.getFlag 可能不存在；本地兜底，语义与 s-root.js L31 一致
  if (typeof S.getFlag !== 'function') {
    var __printFlags = Object.create(null);
    S.getFlag = function (name, dflt) { return name in __printFlags ? __printFlags[name] : dflt; };
  }
  if (typeof S.setFlag !== 'function') {
    S.setFlag = function (name, v) { /* 独立页无需切换，保留接口 */ };
  }
```

- 优点：只改 1 个文件、不影响 index.html、不引入 s-root.js 的路由副作用。
- `reportV2` 默认 true（`getFlag('reportV2', true)`），行为与预期一致。

### 方案 B：`report.html` 引 `s-root.js`

在 `report.html` 加 `<script src="./s-root.js" defer></script>`。**不推荐**：`s-root.js` 会创建 `#sRoot`、跑工作台路由、可能改 `body[data-view]`，在打印页引入影子工作台，副作用大。

### 方案 C：`s-print.js` 局部去掉 getFlag 依赖

把 `enabled()` 改为 `return true`（或读 `location.search` 里的 flag）。可行但丢失 flag 回退能力，偏离 04/05 册。

## 5. 连带修复（同一轮一起做）

1. **导出菜单点击行为降级确认**：CodeBuddy 已如实说明——独立页没有 `window.__exportCtx`，即使初始化修好，`exportManifest({})` 拿到空 ctx 可能返回 0 行/`empty:true` 项，点导出项只会 flash「导出请求已提交」/「引擎未就绪」，**不会真下载 CSV**。
   - **裁定：接受此降级，但必须在 UI 上如实告知**（不能让用户以为导出成功）。P0 修好后，我会实测 12 项的 `count` 标注和点击 flash 文案；若出现「导出请求已提交」但实际无下载，判为误导性文案，需改为「请到研报视图导出」或明确「预览页不支持下载」。
   - 完整导出保留在研报视图（app.js 的 `#expMenu`），符合"前端不写取数逻辑"纪律。

2. **验收脚本口径纠正（WorkBuddy 侧已做，无需 CodeBuddy 改）**：
   - 启用 `Runtime.enable`，早期异常不再漏采（首轮"控制台零异常"是假的）。
   - `.s-prose__toc` 拆分：04 册 L649 只要求隐藏 topbar/nav/tabs/ticker/抽屉/按钮，toc 不在权威清单——不作门禁。
   - 阶段 4a 自检 CLS 按 baseline 0.174（not degraded）判定，不用严格 0.10（`runSelfTest().pass` 冷/热态波动，4a 轮已归档同类现象）。
