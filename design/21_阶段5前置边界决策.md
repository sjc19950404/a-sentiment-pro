## 2. ① overview URL flag：可做，但 05 册字面版有致命分叉

### 2.1 两个分叉（CodeBuddy 未提及，必须先钉死）

线上现状（实测 `_s5_s-root.js` L29-31）：
```js
const flags = Object.create(null);
S.setFlag = (name, val) => { flags[name] = val; return val; };
S.getFlag = (name, dflt) => (name in flags ? flags[name] : dflt);
```
- `S.getFlag(name, dflt)`：未设置时返回**调用方默认**。
- `s-page-overview.js` L102：`overviewEnabled() { return S.getFlag('overview', true) !== false; }` → **overview 默认开**（阶段 2/3 主体行为）。

05 册 L29-57 权威契约：
```js
S.flags = {
  overview: read("overview", false),   // 默认 false！
  ...
};
function read(key, fallback) {
  if (params.has("sflag-" + key)) return params.get("sflag-" + key) === "1";
  if (hasOwnProperty(stored, key)) return Boolean(stored[key]);
  return fallback;                      // false
}
S.setFlag = function (key, value) { S.flags[key] = Boolean(value); ... };
```
- 所有 flag 默认 **false**（含 overview）。
- **只有 `S.flags` 对象 + `S.setFlag`，没有 `S.getFlag` 方法**。

若照 05 册字面替换 s-root.js：① overview 默认由开变关 → 阶段 2/3 总览页白做；② `S.getFlag` 消失 → overview/tableV2/drawerV2/reportV2/defaultWorkbench 全部调用点崩。**这是必须先纠正的契约分叉，不是实现细节。**

### 2.2 正确做法：兼容性升级（保留线上 API，只叠加解析层）

```js
// s-root.js 顶部，替换 L29-31
var params = new URLSearchParams(location.search);
var stored = {};
try { stored = JSON.parse(localStorage.getItem('sFlags') || '{}'); } catch (e) { stored = {}; }
function readFlag(name, dflt) {
  var key = 'sflag-' + name;
  if (params.has(key)) return params.get(key) === '1';
  if (Object.prototype.hasOwnProperty.call(stored, name)) return Boolean(stored[name]);
  return dflt;                                   // 关键：保留调用方默认，overview 仍默认 true
}
// 预置已知 flag 的 URL/localStorage 覆盖，但默认走各调用点语义
S.flags = {
  mount: readFlag('mount', false),
  overview: readFlag('overview', true),          // 与线上一致，默认开
  tableV2: readFlag('tableV2', true),
  drawerV2: readFlag('drawerV2', true),
  reportV2: readFlag('reportV2', true),
  defaultWorkbench: readFlag('defaultWorkbench', false)  // 默认研报，绝不误切
};
var flags = Object.create(null);
S.setFlag = function (name, val) {
  flags[name] = Boolean(val);
  S.flags[name] = Boolean(val);
  try {
    var merged = Object.assign({}, stored, S.flags);
    localStorage.setItem('sFlags', JSON.stringify(merged));
  } catch (e) {}
  return val;
};
S.getFlag = function (name, dflt) {
  if (name in flags) return flags[name];         // 运行时 setFlag 优先
  if (Object.prototype.hasOwnProperty.call(S.flags, name)) return S.flags[name];  // URL/storage 覆盖
  return dflt;                                   // 兜底调用方默认
};
```

契约要点：
- **保留 `S.getFlag(name, dflt)` 签名**——所有现有调用点零改动。
- **默认语义与线上一致**：overview/tableV2/drawerV2/reportV2 默认 true（这些是阶段 2-4 已上线特性），defaultWorkbench 默认 **false**（默认研报铁律）。
- URL 入口 `?sflag-overview=0` / `?sflag-defaultWorkbench=0` 对齐 05 册 L60 回滚示例。
- localStorage 持久化 + setFlag 写回，刷新后仍生效（解决"纯内存刷新即失效"）。
- **不改变默认视图**：实测 s-root.js `route()` L135 `wantBench = view === 'workbench'`，不读 defaultWorkbench flag；阶段 5 才改默认路由。故升级 flag 不触发视图切换。

### 2.3 s-print.js 兜底的处理
s-print.js L22-28 有独立 getFlag/setFlag 兜底（因独立页不引 s-root.js）。升级 s-root.js 后，index.html 侧的 flag 走权威实现；report.html 独立页仍走自身兜底——两者互不干扰，**s-print.js 兜底保留不动**（其 `reportV2` 默认 true 已由兜底 + `getFlag('reportV2', true)` 保证）。
